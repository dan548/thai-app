# Личный доступ и резервные копии

Публичный ключ Supabase допускается в браузере. Защиту обеспечивает RLS:
все таблицы с личными данными доступны только UUID владельца в `public.app_owner`.
Другие аккаунты, включая созданные через публичную регистрацию, доступа не получают.
Таблица владельца недоступна для изменения клиентом.

## Установка

1. В Supabase → Authentication → Users создай подтверждённого пользователя
   `sibraine@proton.me` с собственным паролем. Пароль не записывается в проект.
2. До изменения политик сохрани четыре таблицы в JSON. Копия перед текущими
   изменениями создана 5 октября 2026 года отдельно от репозитория.
3. Выполни в SQL Editor: `supabase/secure-owner.sql`, затем
   `supabase/save-grade.sql`, `supabase/learning-workflows.sql` и
   `supabase/restore-backup.sql`.
4. Обнови приложение. Вход использует email и пароль; регистрацию приложение
   не предлагает. По возможности отключи создание новых пользователей в Supabase.
5. Проверь вход владельца и запрет доступа для анонимного клиента и другого аккаунта.

`schema.sql` для новых проектов закрывает клиентский доступ по умолчанию.
Запуск без переменных Supabase показывает инструкцию вместо падения.
Смена email владельца не передаёт владение: доступ привязан к UUID.

## Сохранение

Оценка карточки и активность сохраняются одной транзакцией через `save_grade_once`.
Сервер блокирует фразу и вычисляет новую ступень из актуального прогресса.
Поэтому две разные оценки с разных устройств не затирают друг друга.
Каждая оценка получает UUID, который сохраняется до подтверждения записи.
Журнал `grade_operations` отличает новую оценку от повтора: повтор с тем же
UUID возвращает результат без изменения прогресса, даже после другой оценки.
Журнал доступен только владельцу; это служебные данные, не входящие в экспорт.
После обновления SQL старый RPC с `target_box` больше недоступен клиентам —
необходимо обновить приложение и открытые вкладки. Карточка остаётся на месте при ошибке.
Временные ошибки повторяются до трёх раз; ошибки доступа не повторяются.
Работа без подключения с локальной очередью пока не реализована.

Выбор слов из видео сохраняется одной транзакцией (`choose_video_words`).
Закрытие окна ничего не записывает. Ошибка оставляет выбор на месте.
Решения по входящим и результаты миссий защищены тем же RLS владельца.

## Резервная копия

В «Прогресс» доступны экспорт и восстановление JSON. Экспорт читает исходные
фразы из базы, сохраняя женские частицы независимо от выбранного профиля.
Копия версии 2 также включает решения по фразам и результаты миссий.
Копии версии 1 поддерживаются и не изменяют новые таблицы.
Большие таблицы читаются порциями. Желательно экспортировать вне занятия:
экспорт нескольких таблиц не является единым снимком транзакции.

Учебный день рассчитан по Asia/Bangkok и совпадает в браузере и базе.

Перед импортом приложение проверяет структуру, показывает количество записей
и предлагает явную кнопку восстановления. Оно также скачивает текущую копию.
Сохрани этот файл, прежде чем закрывать страницу. Импорт выполняется одной
транзакцией с проверкой RLS: ошибка откатывает весь импорт. Совпадающие UUID/дни
заменяются данными копии; остальные записи остаются. Это восстановление с
объединением, а не удаление данных, отсутствующих в файле.

Для восстановления новой базы выполни `schema.sql`, настрой владельца и функции,
войди и импортируй JSON. Не запускай seed повторно поверх восстановленной базы.

## Проверки 5 октября 2026

Проверены доступ владельца, отсутствие чтения и записи у другого UUID,
транзакционное сохранение оценки/активности и повтор одинаковой оценки.
Также проверены импорт и откат ошибочного импорта. Повторяемый SQL-тест —
`supabase/security-check.sql`; проверочные изменения выполняются с ROLLBACK. Количество исходных записей
сохранено: 226 фраз, 2 записи прогресса, 1 день активности.

Supabase Advisor сообщил об отключённой проверке скомпрометированных паролей.
Её доступность зависит от тарифа; настройка находится в Authentication.
Подробнее: [проверка паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Новые сценарии проверяет `supabase/learning-check.sql`: выбор видео, возврат
от «уже знаю» к изучению, копии v2 и запрет чужого доступа. Изменения откатываются.
После применения SQL и проверок исходные данные сохранились: 226 фраз,
2 записи прогресса и 1 день активности. Перед обновлением создана отдельная копия.

Версии зависимостей закреплены в package.json и lockfile. Next.js обновлён
до 15.5.27; PostCSS 8.5.29 задан через overrides, поскольку Next.js 15
закрепляет уязвимую 8.4.31. После обновления npm audit не обнаружил уязвимостей.

Проект использует явный ESM (`type: module`), включая тесты. Минимальная
версия Node.js — 22, в соответствии с установленным Supabase SDK. Проверки
тестов и сборки запускаются на Node.js 22 в GitHub Actions.
