# Установка Thai Trainer в Codex

Веди установку по-русски как разговор: по одному вопросу, с короткими
обновлениями прогресса. Не спрашивай повторно уже известное или разрешённое.
Это аналог `.claude/skills/setup/SKILL.md` для Codex. Пути ниже — от корня
репозитория (package.json с именем thai-trainer). Прочитай `CLAUDE.md`,
`docs/manual-setup.md`, `docs/security.md` и `.env.example` перед установкой.

## 0. План

Покажи план: опрос → проект и схема → владелец и защита → контент →
`.env.local` → запуск и проверка → необязательный деплой. Ориентир — около
20 минут, время зависит от входа в сервисы. Нужны Node.js 22+, аккаунт Supabase
и доступ через MCP/коннектор или CLI; для публикации — Vercel.
Проверь версию Node.js и доступные инструменты. Если установка уже запрошена,
переходи к опросу без повторного подтверждения старта.

## 1. Опрос

Уточняй по одному: имя, пол (`female`/`male` для вежливой частицы), страну,
email владельца и темы. Предложи семь тем: База, Числа, Кофейня, Кафе,
Магазин, Рынок, Массаж; спроси о дополнительных. Пароль не спрашивай и не
записывай: пользователь задаёт его сам в Supabase.

## 2. Supabase и владелец

Используй доступный Supabase MCP/коннектор или авторизованный CLI. При наличии
навыка Supabase следуй ему. Если подключения нет, помоги подключить Supabase
через настройки Codex по текущей официальной документации:
https://supabase.com/docs/guides/ai-tools/mcp . Не записывай конфигурацию Claude
как конфигурацию Codex. Авторизацию пользователь проходит сам. При отсутствии
интеграции веди его по `docs/manual-setup.md`, по одному шагу, автоматизируя
локальную часть. Не сообщай об успешном SQL без результата выполнения.

Выбери с пользователем новый проект или существующий пустой; при создании
уточни организацию, название, регион и тариф. Не создавай платные ресурсы
без согласованного тарифа. До записи проверь целевой проект и таблицы.
На базе с данными не запускай установочный SQL и seed автоматически: предложи
использовать существующую базу или отдельный проект. Не заменяй владельца.

Для пустой базы выполняй SQL целиком в этом порядке:

1. `supabase/schema.sql` — клиентский доступ изначально закрыт.
2. Попроси пользователя создать владельца в Authentication → Users → Add
   user с email из опроса, своим паролем и Auto Confirm User. Дождись
   подтверждения; проверь наличие пользователя доступным инструментом.
3. `supabase/secure-owner.sql`: подставь email только в отправляемый запрос,
   вместо `$email$owner@example.com$email$`, файл репозитория не меняй.
   Если email содержит маркер `$email$`, выбери свободный SQL-маркер, чтобы
   значение оставалось строкой. При ошибке отсутствующего владельца проверь
   email/создание пользователя; не ослабляй защиту.
4. `supabase/save-grade.sql`, `supabase/learning-workflows.sql`,
   `supabase/restore-backup.sql`.
5. `supabase/seed.sql`, затем `supabase/seed-decisions.sql`. Seed с фразами
   запускай один раз. При продолжении после ошибки проверь выполненные шаги,
   не повторяй seed из-за ошибки последующего шага.
6. `supabase/security-check.sql` и `supabase/learning-check.sql` — проверки
   откатывают изменения. Проверь число и наличие стартовых фраз.
7. Помоги отключить регистрацию новых пользователей в Authentication и,
   если доступно на тарифе, включить проверку скомпрометированных паролей.
8. Получи Project URL и publishable (либо совместимый legacy anon) ключ.
   Secret/service_role ключ нельзя помещать в `NEXT_PUBLIC_*` или браузер.

## 3. Личные фразы

Добавь «Меня зовут {имя}» и «Я из {страны}» с точным тайским написанием,
транскрипцией с тонами и русским переводом: `source='chat'`, `deck='base'`,
`hidden=false`. В базе храни женскую частицу ค่ะ/คะ и соответствующую
транскрипцию; мужской вариант подставляет `lib/profile.js`. При возобновлении
сначала проверь существующие фразы, не создавай дубли. Используй параметры
или корректное SQL-экранирование пользовательских значений.
На этой новой базе выполни `seed-decisions.sql`, чтобы intro-фразы получили
решение «Учить». Наполнение заверши до первой учебной сессии.

## 4. Дополнительные темы

По запросу добавь выверенные фразы в существующие колоды `base`, `num`,
`coffee`, `resto`, `shop`, `market`, `massage` (новая тема — в ближайшую,
обычно `base`). Схему без необходимости не меняй. Соблюдай правила частиц
и дедупликации из шага 3, затем выполни `seed-decisions.sql` на новой базе.
Для базы с прогрессом используй `decide_phrase` только для конкретных новых
фраз, не массовый установочный SQL. Реплики тайцев и учебные определения
с пометкой пола не адаптируй.

## 5. Настройки

Создай `.env.local` по `.env.example`:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=<project-url>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable-or-anon-key>
NEXT_PUBLIC_USER_NAME=<имя>
NEXT_PUBLIC_USER_GENDER=<female-or-male>
```

Не перезаписывай существующие настройки вслепую. Соблюдай dotenv-синтаксис
для имени, проверь исключение файла из Git. Не показывай ключи/содержимое
файла в отчёте и не коммить их. Пароль владельца в проекте не хранится.

## 6. Запуск и проверка

Установи закреплённые зависимости (`npm ci` при наличии lockfile, иначе
`npm install`), выполни `npm test` и `npm run build`, затем `npm run dev`.
Следуй требованиям окружения для долгоживущего сервера. Открой фактический
локальный URL в доступном браузере Codex. Пользователь входит сам.
Проверь приветствие, загрузку фраз, новые карточки и сохранение оценки после
перезагрузки. Если нет доступа к браузеру/входу, дай шаги проверки пользователю
и явно укажи, что ещё не проверено. Не имитируй успешный вход.

## 7. Публикация по желанию

Предложи Vercel после локальной проверки. По запросу используй доступную
интеграцию/CLI или помоги импортировать репозиторий, задать те же четыре
переменные и опубликовать. Не меняй провайдера по умолчанию. Проверь URL и
вход владельца, дай ссылку и реальные оставшиеся шаги. Учётные данные
пользователь вводит сам.

Видео и пополнение слов доступны через Codex: правила и
`scripts/fetch_transcripts.py` описаны в `CLAUDE.md`; не меняй плейлист без
запроса. Экспорт/восстановление — в «Прогрессе»; seed поверх восстановленной
базы не запускать.
