# Установка Thai Trainer

Ты ведёшь пользователя через установку как разговор. Не вываливай всё сразу —
иди по шагам, задавай по одному вопросу, показывай прогресс.

## Шаг 0. Роадмап
Покажи план и оценку (~20 минут). Что понадобится: Node.js 22+, аккаунт Supabase
и подключённый Supabase-коннектор к Claude; по желанию — Vercel для деплоя.
План: опрос → проект и схема → владелец и защита → контент → `.env.local` →
запуск и проверка → деплой. Приложение личное: вход по email и паролю только
для одного владельца, регистрации нет. Спроси, готов ли начать.

## Шаг 1. Опрос (по одному вопросу)
1. Имя (как обращаться, пойдёт в приветствие «สวัสดี …»).
2. Пол — женский или мужской (определяет вежливую частицу ค่ะ/คะ vs ครับ).
3. Страна (для фразы «я из …»).
4. Email владельца — им пользователь будет входить в приложение. Пароль не
   спрашивай и нигде не записывай: его пользователь задаёт сам в Supabase.
5. Покажи 7 тем: База, Числа, Кофейня, Кафе, Магазин, Рынок, Массаж.
   Спроси: все подходят? Что-то добавить?

## Шаг 2. База Supabase и защита владельца
Порядок важен: защита ставится до того, как приложение откроют в браузере.
Это сценарий для пустого проекта: на базе с данными `seed.sql` и
`seed-decisions.sql` не запускай (дубли фраз, потеря «Входящих»).
Все SQL-файлы лежат в `supabase/`, выполняются целиком и не требуют правок,
кроме `secure-owner.sql`.

1. Если коннектор подключён: создай новый проект (или предложи существующий —
   только пустой; в базе с данными ничего не перезаписывай) или попроси
   пользователя создать проект и дай его ссылку. Без коннектора — отправь к
   `docs/manual-setup.md` и помоги по шагам.
2. Выполни `schema.sql` (таблицы закрыты для клиента по умолчанию).
3. Попроси пользователя в Supabase → Authentication → Users → Add user →
   Create new user создать пользователя с email из опроса, своим паролем и
   включённым Auto Confirm User. Дождись подтверждения. Пароль тебе не нужен.
4. Выполни `secure-owner.sql`, подставив email владельца в `owner_email`
   (в файле стоит заглушка `$email$owner@example.com$email$`; оставь маркеры
   `$email$`, сам файл в репозитории не меняй, правь только текст запроса;
   email должен точно совпадать с созданным пользователем). Ошибка «Сначала создайте владельца» — значит,
   пользователя ещё нет или email не совпал.
5. Затем по очереди: `save-grade.sql`, `learning-workflows.sql`,
   `restore-backup.sql`.
6. Выполни `seed.sql`, затем `seed-decisions.sql` (стартовые фразы сразу идут в
   занятия; слова из видео остаются на выбор). Повторно seed не запускай.
7. Прогони `security-check.sql` и `learning-check.sql` — оба откатывают
   изменения; ошибок быть не должно. Сверь число фраз с ожидаемым (≈224).
8. Попроси пользователя в Authentication отключить регистрацию новых
   пользователей (Sign In / Providers → Allow new users to sign up: выкл.) и,
   если тариф позволяет, включить проверку скомпрометированных паролей.
9. Забери Project URL и anon (publishable) ключ.

## Шаг 3. Личные intro-фразы
Сгенерируй под пользователя и вставь в `phrases` с `source='chat'`, `deck='base'`,
`hidden=false` (частицу подставь по полу: жен. ค่ะ, муж. ครับ):
- «Меня зовут {имя}» → `ฉันชื่อ{имя}{частица}`
- «Я из {страны}» → `มาจาก{страна}{частица}`
Транскрипцию дай с тонами. Имя/страну по-тайски — транслитерируй аккуратно.
Фразы с `source='chat'` без решения лежат во «Входящих», поэтому после вставки
снова выполни `seed-decisions.sql` — он добавит им решение «Учить».

## Шаг 4. Дополнительные темы
Если пользователь просил темы сверх семи — добавь выверенные фразы с
`source='chat'`, строгий тайский с тонами и нужной частицей, без выдумок.
Допустимые колоды ограничены ограничением в схеме (`base`, `num`, `coffee`,
`resto`, `shop`, `market`, `massage`): новая тема идёт в ближайшую колоду
(чаще `base`); схему без необходимости не меняй. Затем снова выполни
`seed-decisions.sql`.

## Шаг 5. .env.local
Создай `.env.local` (см. `.env.example`):
```
NEXT_PUBLIC_SUPABASE_URL=<url>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
NEXT_PUBLIC_USER_NAME=<имя>
NEXT_PUBLIC_USER_GENDER=<female|male>
```
Файл в `.gitignore`; не показывай и не коммить ключи.

## Шаг 6. Запуск
```
npm install
npm test
npm run dev
```
Открой http://localhost:3000. Появится экран входа: войди email и паролем
владельца. Убедись, что после входа есть приветствие с именем, фразы грузятся,
оценка карточки сохраняется (после перезагрузки прогресс на месте). Для
проверки сборки: `npm run build`.

## Шаг 7. Деплой (по желанию)
Предложи Vercel: импорт репозитория, те же 4 переменные окружения в настройках
проекта, деплой. Дай ссылку на прод и проверь вход владельца там же.

## Заметки
- Частица в UI подставляется автоматически (`lib/profile.js`) — в базе всегда
  женский вариант, не дублируй мужской.
- Реплики тайцев (THEY_SAY, роли `thai` в диалогах) частицу не меняют.
- Решения по фразам (`phrase_decisions`) и миссии (`mission_results`) создаёт
  `learning-workflows.sql`; без него приложение не заработает полностью.
- Экспорт/восстановление JSON — в «Прогрессе»; на новой базе seed поверх
  восстановленных данных не запускать (см. `docs/security.md`).
- 12 видео в `lib/data.js → VIDEOS` — стартовый тайский плейлист; его можно
  заменить, попросив Claude (см. `scripts/fetch_transcripts.py`).
